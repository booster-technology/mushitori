# ムシトリ 仕様書

お客様との不具合・要望・質問のやり取りを管理する課題管理ツールの仕様をまとめる。
操作方法は画面の「使い方」、設置方法は [README.md](../README.md)、開発時の注意点は [CLAUDE.md](../CLAUDE.md) を参照。

## 1. 概要

- 受託開発・Web制作・システム保守など「お客様から不具合報告を受ける仕事」向けの、必要な機能に絞った課題管理ツール
- お客様がスクリーンショットを添えて課題を起票し、社内メンバーが担当者・状態を管理しながらコメントでやり取りする
- パスワードは使わず、メールに届く6桁の認証コードでログインする
- 日本語のみ。PC・タブレット・スマホに対応する

## 2. 利用者と権限

### 2.1 ロールとポータル

| ロール | 使う画面(ポータル) | ログイン画面 | 説明 |
|:--|:--|:--|:--|
| 社内メンバー | 社内用 `/{STAFF_PATH}/...`(既定 `/staff`) | `/staff/login` | 自社の担当者。全プロジェクトを見られ、管理機能を使える |
| お客様 | お客様用 `/...` | `/login` | 参加しているプロジェクトだけを見られる |

- ユーザーは1つの表で管理し、ロール(`users.role`)で区別する。社内用とお客様用はログイン状態が別で、同じブラウザで両方に同時にログインできる
- 一方のポータルでログアウトしても、もう一方のログイン状態は消えない
- 社内用画面のURL(`STAFF_PATH`)は推測されにくい文字列に変えられる(インストール時に設定。お客様用の画面と重なる名前は使えない)

### 2.2 権限

| 操作 | 社内メンバー | お客様 |
|:--|:--|:--|
| プロジェクトの閲覧 | 全プロジェクト | 参加しているプロジェクトのみ |
| 課題の起票・コメント・状態の変更 | ○ | ○ |
| 課題の編集(件名・種別・詳細・添付) | ○ | 自分が起票した課題のみ(社内メンバーが代わりに登録した課題を含む。添付の削除は自分が添付したもののみ) |
| 担当者・優先度・期限日の変更 | ○ | × |
| お客様の代わりに起票(代理起票) | ○ | × |
| 課題の削除 | ○ | × |
| コメントの削除 | ○(すべて) | 自分のコメントのみ |
| プロジェクト管理・ユーザー管理・ゴミ箱 | ○ | × |

- お客様が見られないプロジェクト・課題・コメント・添付ファイルは、閲覧以外の操作(削除など)でも 403 ではなく 404 を返し、存在自体を知らせない

## 3. 画面一覧

| 画面 | お客様用URL | 社内用URL | 内容 |
|:--|:--|:--|:--|
| ログイン(メール入力) | `/login` | `/staff/login` | メールアドレスを入力すると認証コードを送る。登録の有無に関わらず同じ表示(アカウントの有無を推測させない) |
| ログイン(コード入力) | `/login/code` | `/staff/login/code` | 6桁のコードを入力。再送・ログイン状態の保持(30日)を選べる |
| ホーム | `/` | `/staff` | プロジェクト一覧(状態別の件数)、最近更新された課題(10件)。社内は「自分が担当の未完了課題」も表示 |
| 課題一覧 | `/projects/{キー}/issues` | `/staff/projects/{キー}/issues` | 状態タブ・絞り込み・キーワード検索・並び替え・20件ずつのページング。PCは表、スマホはカード表示 |
| 課題の追加 | `/projects/{キー}/issues/create` | `/staff/projects/{キー}/issues/create` | 種別を選ぶと記入テンプレートを入力欄に入れる。担当者・期限日・起票者(代理起票)は社内のみ指定できる |
| 課題詳細 | `/issues/{課題キー}` | `/staff/issues/{課題キー}` | 本文・添付・コメント(変更履歴を含む)・コメント投稿欄(状態などの変更も) |
| 課題の編集 | `/issues/{課題キー}/edit` | `/staff/issues/{課題キー}/edit` | 件名・種別・詳細・添付の追加と削除 |
| 使い方 | `/help` | `/staff/help`(お客様向けは `/staff/help/customer`) | 操作説明。お客様向けには社内用のURLや管理機能を載せない |
| プロジェクト管理 | - | `/staff/projects` | 一覧(20件ずつ)・作成・編集・削除・メンバーの追加と外す操作 |
| ユーザー管理 | - | `/staff/users` | 一覧(ロールで絞り込み・氏名/メールアドレス/会社名で検索・20件ずつ)・作成・編集・無効化・ログインのロック解除 |
| ゴミ箱 | - | `/staff/trash` | 削除したプロジェクト・課題・コメント・添付ファイルの一覧(種類ごと・20件ずつ)・元に戻す・完全に削除 |

- 一覧・詳細画面には「戻る」ボタンを置く。削除・重要な保存の前には確認ダイアログを出す(ブラウザ標準の confirm は使わない)
- フォームは送信後にボタンを無効にし、二重送信を防ぐ
- エラー画面(404・419・429・500・503 など)・入力チェックのメッセージはすべて日本語

## 4. ログイン

| 項目 | 仕様 |
|:--|:--|
| 方式 | メールアドレスを入力 → 6桁の認証コードをメールで送る → コードを入力してログイン(パスワードは無い) |
| コードの有効期限 | 10分 |
| 1つのコードで間違えられる回数 | 5回(超えると、そのコードは使えない) |
| 再送 | できる。再送すると以前のコードは使えなくなる |
| アカウントのロック | 1つのアカウントで1時間に10回間違えるとロック(最初の入力ミスから1時間で自動解除)。1日に30回間違えると24時間ロック。入力の回数は照合の前に数える(同時に送信しても上限を超えて試せない)。社内メンバーがユーザー編集画面から、またはサーバーで `php artisan app:unlock-login メールアドレス` で解除できる |
| 送信回数の上限 | 同じ宛先へは1時間10回まで(接続元のIPに関係なく) |
| 接続元ごとの上限 | 送信: 同じメールアドレス+IPで1分5回・同じIPで1分20回。確認: 同じIPで1分10回 |
| ログイン状態の保持 | 選んだ場合は30日。選ばない場合は、操作が無いまま120分(`SESSION_LIFETIME`)で切れる |
| 未登録のメールアドレス | 登録済みの場合と同じ表示・同じように入力ミスを数える(登録の有無を推測させない) |
| 無効にされた・ロールが変わったユーザー | 次の操作で強制的にログアウトする(ログイン状態の保持も取り消す) |
| その他 | 認証コードはハッシュにして保存する。最終ログイン日時を記録する。使い終わった・期限切れのコードは毎日削除する |

## 5. プロジェクト

| 項目 | 仕様 |
|:--|:--|
| キー | 必須。英大文字で始まる2〜10文字(英大文字・数字・`_`)。重複不可。小文字で入力しても大文字にする。**作成後は変更できない**(課題キー・URLが変わるため) |
| 名前 | 必須。100文字まで |
| 説明 | 任意。2000文字まで |
| メンバー | 社内メンバー・お客様を追加する。お客様は参加しているプロジェクトだけを見られる。社内メンバーのメンバー登録は通知先(9章)に使う |
| 削除 | ゴミ箱に移す(10章)。プロジェクト内の課題も見えなくなる |

## 6. 課題

### 6.1 項目

| 項目 | 仕様 |
|:--|:--|
| 課題キー | `プロジェクトキー-番号`(例: `WEB-12`)。番号はプロジェクトごとに1からの連番(同時に登録しても重複しない) |
| 件名 | 必須。200文字まで |
| 種別 | 不具合 / 要望 / 質問 / その他。不具合・要望・質問は、選ぶと詳細欄に記入テンプレート(操作手順・期待する動作・実際の動作など)を入れる |
| 詳細 | 任意。20000文字まで。改行・URL(リンクになる)を表示する |
| 状態 | 未対応 → 処理中 → 処理済み → 完了(どの状態にも変更できる)。登録時は未対応 |
| 優先度 | 高 / 中 / 低(必須) |
| 担当者 | 任意。有効な社内メンバーのみ |
| 期限日 | 任意。完了以外で期限を過ぎていると赤字で表示する |
| 起票者 | 課題を登録した人(変更できない)。社内メンバーは登録時に、そのプロジェクトに参加している有効なお客様を起票者に選べる(代理起票。電話・メールで受けた内容の登録用)。その場合は代わりに登録した社内メンバーも記録し、課題詳細に「(氏名 が代わりに登録)」と表示する。お客様の画面には選択欄が無く、送られても無視する |
| 添付ファイル | 8章 |

- 完了にすると完了日時を記録し、完了以外に戻すと消す
- 状態・担当者・優先度・期限日は、課題詳細のコメント欄から変更する(変更はコメントに履歴として残る)。課題の編集画面では変更しない

### 6.2 課題一覧

| 項目 | 仕様 |
|:--|:--|
| 状態の絞り込み | 完了以外(既定) / すべて / 各状態 |
| その他の絞り込み | 種別・優先度・担当者(自分 / 未設定 / 社内メンバー) |
| キーワード検索 | 件名・詳細の部分一致。`WEB-12` のように課題キーを入力した場合はその課題 |
| 並び替え | 更新日時が新しい順(既定) / 登録日時が新しい順 / 優先度が高い順 / 期限日が近い順 |
| ページング | 20件ずつ |

## 7. コメントと変更履歴

- コメント欄から、本文・添付ファイルと一緒に状態などを変更できる。本文・添付・変更のどれも無い場合はエラー
- 変更できる項目: お客様は状態のみ、社内メンバーは状態・担当者・優先度・期限日
- 変更内容(何から何に変えたか)はコメントに履歴として記録し、課題詳細に表示する
- 本文は20000文字まで。コメントがあると課題の更新日時を更新する
- コメントの削除: 社内メンバーはすべて、お客様は自分のコメントのみ。削除するとコメントの添付ファイルも一緒にゴミ箱に移す。画面には「削除されました」と変更履歴だけを表示する

## 8. 添付ファイル

| 項目 | 仕様 |
|:--|:--|
| 形式 | png / jpg / jpeg / gif / webp / pdf / txt / log / csv / xlsx / xls / docx / doc / pptx / ppt / zip / mp4 / mov |
| 大きさ・数 | 1ファイル10MBまで、1回の投稿で10ファイルまで |
| 追加方法 | ファイル選択・ドラッグ＆ドロップ・Ctrl+V(スクリーンショットの貼り付け)。送信前にプレビューを表示する |
| 形式のチェック | 拡張子とファイルの中身の両方を確認する。SVG・HTML などは不可。画像の拡張子なら中身も画像であること。画像は5000万画素まで |
| 画像の縮小 | 長辺2560pxを超える画像は、送信前にブラウザで縮小する(縮小後に10MB以下になれば、元が10MB超の写真も添付できる)。ブラウザで縮小できなかった場合はサーバーで同じ形式のまま縮小する(PNGは可逆・透過を保つ。JPEGは向きを反映し、位置情報などは消える。GIFはアニメーションを保つため縮小しない) |
| サムネイル | 画像は一覧用のサムネイル(最大480×360のJPEG)を自動で作る。クリックで拡大表示 |
| 画像以外 | ダウンロードになる(ブラウザで開かない) |
| 保存先 | ファイルはサーバーのストレージ(`storage/app/private`)、DBには名前・大きさなどの情報だけ |
| 閲覧 | その課題を見られる人だけ(毎回権限を確認する)。見られない人には404 |
| サーバーの負荷 | 画像は1つずつ処理し、1リクエストのメモリは `IMAGE_MEMORY_LIMIT`(既定256MB)まで。超える巨大な画像は縮小・サムネイル作成をせずにそのまま保存する |
| 連続投稿の制限 | 課題の登録・編集・コメントの投稿は、1人1分20回まで |

## 9. メール通知

| きっかけ | 宛先 |
|:--|:--|
| 課題の登録 | プロジェクトの社内メンバー(1人もいなければ社内全員)+ 担当者。代理起票の場合は起票者のお客様にも(「お問い合わせいただいた内容を課題として登録しました」という文面) |
| コメント・状態などの変更 | 起票者 + 担当者 + その課題にコメントしたことがある人。お客様が投稿した場合は、プロジェクトの社内メンバー(1人もいなければ社内全員)にも |
| ユーザーの作成(任意) | 作成したユーザー本人(ログインURLと方法の案内) |
| ログイン | 本人(6桁の認証コード) |

- 操作した本人・無効なユーザー・その課題を見られない人(プロジェクトから外れたお客様など)には送らない
- メール内のリンクは受信者のポータル(社内用 / お客様用)のURLで、常に `APP_URL` を基準に作る
- 送信に失敗しても課題の登録などは成功させ、失敗はログに残す
- 1人ずつ通知を選ぶ機能(ウォッチ)は無い

## 10. 削除とゴミ箱

- プロジェクト・課題・コメント・添付ファイルの削除は、すべて**論理削除**(データもファイルも残し、画面と配信からは見えなくする)。削除した日時と削除した人を記録する
- 削除したものはゴミ箱に移り、保管期間(`TRASH_RETENTION_DAYS`、既定30日)のあいだ社内メンバーが元に戻せる。プロジェクト・課題が削除されたままのコメント・添付ファイルは元に戻せない(先に親を戻す)
- 保管期間を過ぎたものは、毎日4時に添付ファイルの実体も含めて完全に削除する(`TRASH_RETENTION_DAYS=0` なら自動では削除しない)
- 社内メンバーはゴミ箱の「完全に削除」で、すぐに完全に削除できる(個人情報が写った画像を誤って添付した場合など。誰が消したかはログに残す)
- 課題・プロジェクトを完全に削除すると、その中のコメント・添付ファイルも完全に削除する。コメントを完全に削除しても、状態などの変更履歴は課題の経緯として残す
- ユーザーは削除せず「無効」にする

## 11. ユーザー管理

| 項目 | 仕様 |
|:--|:--|
| 氏名 | 必須。100文字まで |
| メールアドレス | 必須。重複不可(大文字・小文字は区別しない)。ログインに使う |
| ロール | 社内 / お客様 |
| 会社名 | お客様のみ。100文字まで |
| 参加プロジェクト | 複数選べる |
| 有効 / 無効 | 無効にするとログインできなくなり、ログイン中なら次の操作でログアウトする |
| ログイン案内メール | 作成時に送るか選べる |

- 自分自身を無効にしたり、お客様に変えたりはできない
- 一覧は有効なユーザーを先に、会社名順に表示する
- 社内メンバーが全員ログインできなくなった場合は、サーバーで `php artisan app:create-staff メールアドレス` で追加・復旧できる

## 12. 画面の見た目

- サイト名(`APP_NAME`)とテーマカラー(`APP_THEME_COLOR`、既定 `#0D223A`)を変えられる。明るい色でも文字色を自動で調整する
- 社内用画面のヘッダーは、お客様用と見分けやすいよう、テーマに関係なくチャコール+アンバー
- 外部のサイト(CDN・外部フォント・解析ツールなど)には接続しない。Bootstrap・Bootstrap Icons・Alpine.js・Noto Sans JP は同梱している(社内LANでも動く)

## 13. セキュリティ

| 項目 | 仕様 |
|:--|:--|
| 応答ヘッダー | すべての応答に X-Frame-Options・X-Content-Type-Options・Referrer-Policy を付ける。本番では CSP `default-src 'self'`(インラインのスクリプト・スタイル・eval を使わない)も付ける |
| エラー画面 | 本番(`APP_DEBUG=false`)では内部情報を出さず、「問題が発生しました」と表示する。詳細はログに残す |
| ログ | パスワード・認証コード・入力値は記録しない(ユーザーはIDで記録する) |
| 添付ファイルの配信 | 権限を毎回確認する(`Cache-Control: private, no-cache` + ETag)。画像以外はダウンロードで返す |
| ロードバランサー | 信頼する接続元は `.env` の `TRUSTED_PROXIES`(プライベートIPの範囲。`*` は使わない)。X-Forwarded-Host は信頼しない |
| URL | 本番では画面・メールのURLを常に `APP_URL` を基準に作る(Hostヘッダーの偽装でリンクを書き換えられないように) |
| セッションの Cookie | 名前はサイト名(`APP_NAME`)の英数字から作る(日本語だけのサイト名なら `mushitori-session`)。JavaScript からは読めない(httponly) |
| インストール・更新 | Webの画面からはできない(SSHでコマンドを実行する) |

## 14. 設定(.env)

| 設定 | 内容 | 既定 |
|:--|:--|:--|
| `APP_NAME` | サイト名(画面の左上・メール) | ムシトリ |
| `APP_URL` | 公開URL | - |
| `STAFF_PATH` | 社内用画面のURL | `staff` |
| `APP_THEME_COLOR` | テーマカラー | `#0D223A` |
| `TRUSTED_PROXIES` | ロードバランサーの後ろで動かす場合に信頼する接続元 | なし |
| `IMAGE_MEMORY_LIMIT` | 画像処理に使ってよいメモリ(1リクエスト) | 256M |
| `SESSION_LIFETIME` | 操作が無い場合にログインが切れるまでの時間(分) | 120 |
| `MAIL_MAILER` など | メールの送り方(SMTP / Amazon SES(`ses-v2`。EC2のIAMロールで送信) / log(送信しない)) | - |
| `TRASH_RETENTION_DAYS` | ゴミ箱の保管期間(日)。0なら自動で削除しない | 30 |
| `BACKUP_DAILY` | 毎日3時に自動でバックアップする | false |
| `BACKUP_KEEP` | 残すバックアップの数 | 7 |
| `BACKUP_PATH` | バックアップの保存先 | `storage/backups` |
| `MYSQLDUMP_PATH` | mysqldump の場所 | `mysqldump` |
| `LOG_DAILY_DAYS` | ログを残す日数 | 14 |

## 15. 定期実行

cron で毎分 `php artisan schedule:run` を Webサーバー(PHP-FPM)と同じユーザーで実行する。

| 時刻 | 処理 |
|:--|:--|
| 毎日0時 | 使い終わった・期限切れのログイン認証コードを削除する |
| 毎日3時 | バックアップ(`BACKUP_DAILY=true` の場合) |
| 毎日4時 | ゴミ箱で保管期間を過ぎたものを完全に削除する |

## 16. バックアップ

- `php artisan app:backup` で、データベース(MySQLは mysqldump、SQLiteは VACUUM INTO でコピー)・添付ファイル・`.env`・復元手順(RESTORE.txt)を1つのファイル(zip。zip拡張が無ければ tar.gz)にまとめる
- 保存先は `storage/backups`(`BACKUP_PATH`)。新しいものから `BACKUP_KEEP` 個(既定7)を残して古いものを削除する(日数ではなく個数。`update.sh` のたびにも1個作られる)
- `.env` を含めない場合は `--without-env`
- 完全に削除したデータも、バックアップの保管期間のあいだはバックアップに残る

## 17. インストール・アップデート

- SSHでサーバーにログインし、コマンドで行う(Webの画面からのインストール・更新の機能は無い)
- インストール: `bash install.sh`(依存パッケージ(Composer) → `php artisan app:install` で設定の聞き取り・`.env`の作成・データベースの作成・最初の社内メンバーの登録・テストメール)。本番サーバーでは続けて `deploy/setup-server.sh`(書き込み権限・Nginx・cron)を実行できる。HTTPS の証明書がまだ無い場合、Nginx はいったん HTTP の設定にし、`certbot --nginx` で HTTPS にする
- アップデート: `./update.sh`(git で設置した場合のみ。更新前のバックアップ → メンテナンスモード → git pull → 依存パッケージ → データベースの更新 → キャッシュの作り直し)。git pull・composer は実行したユーザーで、artisan は Webサーバーのユーザーで実行する
- 権限: `storage` は Webサーバー(PHP-FPM)の所有、`bootstrap/cache` は設置したユーザーと Webサーバーの両方が書き込める、`.env` は設置したユーザーの所有・Webサーバーのグループ・640。VPS では artisan のコマンドを Webサーバーのユーザーで実行する(`sudo -u apache php artisan …`)

| コマンド | 内容 |
|:--|:--|
| `bash install.sh` | インストール(質問に答える。`--no-interaction` とオプションで自動インストール) |
| `sudo bash deploy/setup-server.sh` | 書き込み権限・Nginx・cron の設定(内容を表示して確認してから実行) |
| `./update.sh` | アップデート |
| `php artisan app:backup` | バックアップ |
| `php artisan app:create-staff メールアドレス` | 社内メンバーの追加・復旧 |
| `php artisan app:unlock-login メールアドレス` | ログインのロック解除 |
| `php artisan app:purge-trash` | 保管期間を過ぎたゴミ箱のデータを完全に削除(毎日自動で実行) |
| `php artisan app:nginx-config --url=URL` | このサーバー用の Nginx 設定を表示 |

## 18. 動作環境

- SSHでコマンドを実行できるサーバー
- PHP 8.3 以上(mbstring・openssl・pdo_mysql または pdo_sqlite・gd・fileinfo・xml・ctype・tokenizer)
- MySQL 8.0 / MariaDB 10.6 以上、または SQLite 3(少人数向け)
- Nginx + PHP-FPM または Apache + PHP-FPM。投稿の上限110MB・処理時間120秒(`deploy/` の設定例)
- メール送信用のSMTPサーバー、または Amazon SES

## 19. データ(主なテーブル)

| テーブル | 内容 |
|:--|:--|
| users | ユーザー(氏名・メールアドレス・ロール・会社名・有効/無効・最終ログイン日時) |
| login_codes | ログイン認証コード(ハッシュ・有効期限・入力回数・使用日時) |
| projects | プロジェクト(キー・名前・説明・次の課題番号) |
| project_user | プロジェクトのメンバー |
| issues | 課題(番号・件名・詳細・種別・優先度・状態・起票者・代わりに登録した人 `registered_by`・担当者・期限日・完了日時) |
| comments | コメント(本文・変更履歴 `change_log`) |
| attachments | 添付ファイルの情報(元のファイル名・保存場所・サムネイルの場所・形式・大きさ・画像の幅と高さ)。ファイル本体はストレージ |
| sessions / cache | ログイン状態・ログインの回数制限など |

- projects・issues・comments・attachments は論理削除(削除日時・削除した人)。完全に削除したコメントは本文を消し、変更履歴だけを残す(`purged_at`)
